# ROM Tuner

Settings app and root daemon for the TB-X606V ROMs (Android 14 and 16). Presets, CPU governor, overclock, GPU clock, thermal limits, I/O, memory, network and behaviour tweaks. Built without Gradle (`sh build.sh`: aapt2, javac, d8, zipalign, apksigner).

<img src="docs/icon-light.png" width="96"> <img src="docs/icon-dark.png" width="96">

Launcher icon: a performance dial in flat colour (no gradients or transparency, so it stays crisp at launcher size). Adaptive icon with a themed (monochrome) layer; the dark variant (`res/drawable-night`) is used when the system is in dark mode.
Sources: `assets/icon.svg`, `assets/icon-dark.svg`.

## Presets
Battery saver, Balanced, Smooth, Performance, Extreme. Measured on the tablet with a scripted Settings fling (`gfxinfo` janky frames) and an 8-thread compute loop:
Battery 7.4% janky / p95 34 ms; Balanced 2.8% / 19 ms; Performance profile 2.6% / 23 ms; Smooth (boosts 60/30, bigger free-memory reserve) 1.7% / 18 ms; Performance preset (boosts 100/70) 1.1% / 22 ms.
Pinning clocks (Overclock) and turning thermal limits off gave no extra UI smoothness. Big-task rotation made the 8-thread compute run 20 to 30% slower, so no preset enables it.
The daemon re-applies the profile every 5 s because the MediaTek power HAL rewrites power mode, boosts and clock limits.

## What it does
Performance profile (battery / balanced / performance, GPU lock, CPU max clocks), dark mode, pure black, accent colour, palette style, font, icon shape,
icon pack, navigation, animation speed, display size, boot animation, logging, shortcuts to system settings, restart UI, reboot. A "Performance" quick-settings tile cycles the profile.

## How it works
The app only appends `key=value` lines to its own `files/request`. A root daemon (`device/tablet_tunerd.sh`, started by `device/tablet_tunerd.rc` at boot)
watches that directory with `inotifyd`, validates the values, applies them and keeps the master state in `/data/local/tmp/tuner.state`
(log: `/data/local/tmp/tuner.log`). It shows up in Settings through the `com.android.settings.action.IA_SETTINGS` intent filter.
The daemon runs as `u:r:su:s0`, so it needs a userdebug ROM with that domain (or permissive SELinux).

## Install (system app)
```sh
adb root; adb shell mount -o remount,rw /
adb shell mkdir -p /system/app/RomTuner
adb push RomTuner.apk /system/app/RomTuner/ ; adb push device/tablet_tunerd.sh /system/bin/ ; adb push device/tablet_tunerd.rc /system/etc/init/
# boot animations the "Boot animation" option switches between:
#   /system/product/media/bootanimation-{galaxy,aurora,stock}.zip
adb shell 'chmod 755 /system/bin/tablet_tunerd.sh; chmod 644 /system/app/RomTuner/RomTuner.apk /system/etc/init/tablet_tunerd.rc; restorecon -R /system/app/RomTuner /system/bin/tablet_tunerd.sh /system/etc/init/tablet_tunerd.rc'
adb reboot
```
Profile writes set `cpufreq_power_mode` before the clock limits (the sports mode otherwise resets them). The MediaTek power HAL clears
`userlimit_min_cpu_freq` on touch boosts, so the daemon re-applies it every 8 s.

The APK is signed with a throwaway key generated by `build.sh` (`tuner.keystore`, not committed), so rebuilt APKs must be installed over a system copy signed with the same key or after uninstalling.
